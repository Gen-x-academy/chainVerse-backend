# Mentorship delivery and staffing (MENTOR-020 / MENTOR-021)

## Scope

- **MENTOR-020** stores a program's `remote`, `in_person`, or `hybrid` delivery mode and publishes only discovery-safe labels.
- **MENTOR-021** assigns coordinators, application reviewers, safeguarding contacts, and finance approvers for an explicit start/end tenure.

## Dependencies and workflow

Both features depend on the existing Mongoose connection, global JWT/role guards, the audit module, and the scheduler. Program writes enter `pending` workflow state and are reconciled by `mentorship-program-workflow`; expired facilitator assignments are revoked by `mentorship-facilitator-expiry`. These operations are retry-safe and expose `failed`/revoked state rather than silently granting access.

## Authorization and privacy boundary

Management endpoints are deny-by-default and limited to authenticated admin/moderator principals. Program owners may update only their own program. Assignment changes are organization/program scoped and require bounded tenure. Reviewers cannot review their own work, and coordinator/reviewer/finance combinations that violate separation of duty are rejected.

Remote instructions are never public. In-person data is limited to country, region, city, and an optional public venue label; exact addresses, coordinates, access codes, and private notes are intentionally not accepted or returned. Discovery responses never expose remote join instructions or facilitator identities.

## Booking safety and idempotency

A program with active bookings cannot change mode or location. Every mutation requires an 8–64 character idempotency key; retries with the same key return the existing result, while conflicting assignment/configuration attempts return stable actionable errors.

## Rollout

1. Deploy schemas and APIs with management roles enabled only for an allowlisted operations group.
2. Monitor `mentorship.program.*` and `mentorship.facilitator.*` OpenTelemetry events and audit records.
3. Backfill broad location and delivery labels before enabling public discovery.
4. Enable remote/in-person/hybrid creation gradually; keep updates blocked for programs with active bookings.

## Related MENTOR work

This builds on the existing mentor profile, availability, trust-indicator, and lifecycle modules. Booking-domain integration should maintain `activeBookingCount` transactionally when booking workflows are expanded; until then, the field fails closed for unsafe configuration changes when non-zero.
